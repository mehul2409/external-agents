## Step 4 — The assumption that broke, and the bug it exposes

We assumed the formats we consume are stable and all-or-nothing. Three
fragilities in `ci/pr-impact/bin/pr-impact.mjs`:

- Lines ~302-303: failure is detected by matching ENGLISH PROSE
  (`/No associated Entire checkpoint/`, `/checkpoint not found/`). A wording
  change silently flips "unreadable" to "readable".
- Line ~312: tier-2 intent parses the HUMAN-RENDERED table of
  `entire checkpoint list` with a layout regex.
- Lines ~94-99: `ndjson()` swallows malformed lines and ignores
  `schema_version`, so a schema shift passes unnoticed.

The real bug: line ~316, `available: resolved > 0` is binary. On our demo run
intent resolved for 3 of 81 commits, and we then reported consumer repos as
"never mentioned in checkpoint intent" while 78 transcripts were unread. We
present partial context as authoritative and manufacture false findings from
it. The Curveball forbids exactly this.

## Step 5 — Implement

Create `ci/pr-impact/lib/transcript.mjs` as the single ingestion layer:

    raw → detectFormat()  → 'legacy-text' | 'jsonl-v2' | 'unknown'
        → parse<format>() → the ONLY per-format code
        → normalize()     → { events, unknownEvents[], completeness, resolved, total }

Everything downstream stays format-agnostic. Do not fork the pipeline per
format.

Replace the binary `available` flag with completeness:

- `complete`   — every commit in range resolved
